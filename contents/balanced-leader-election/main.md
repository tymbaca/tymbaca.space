# Balanced Leader Election

## Leader election
Leader election - процесс, когда несколько нод решают кто из них лидер. 

```
type Election interface {
    IsLeader() bool
}
```

Зачем? В типичных продуктовых приложениях можно встретить cron-джобы - асинхронные воркеры, выполняющую какую-то логику с определенной периодичностью. Например `CancelOutdatedOrdersJob`. 

Так вот, чаще всего нам достаточно, чтобы эта джоба запускалась лишь в одном экземпляре, на одной ноде. И с этим помогает leader election: джобу будет выполнять тот, кто держит лидерство.

```
if election.IsLeader() {
    CancelOutdatedOrdersJob.Run()
}
```


Чем это чревато?

В нашем приложении может быть много фоноввых джоб, требующих leader election. Мы можем пойти двумя путями:
- Использовать один экземпляр `election` на все джобы. В таком случае все джобы будут выполняться на одном инстансе;
- Использовать множество экземпляров `election`, по одному на каждую джобу. В таком случае лидерство может раскидаться рандомно по всем инстансам. Либо все лидерства уйдет в один инстанс, если по какой-то причине остальные ноды задержались

Первый вариант может нам не подойти, особенно в случае когда большая часть работы нашего приложения заключена в крон-джобах. Потому что всю работу будет выполнять одна нода, а остальные будут простаивать, удерживая память и цпу.

Если же мы попытаемся сбалансировать лидерство пойдя вторым путем (грязный хак) - то довольно быстро поймем, что это не лучший вариант. Наши реплики редко стартуют одновременно (точнее, почти никогда). А значит и лидерство почти всегда не будет нормально и предсказуемо сбалансировано.
